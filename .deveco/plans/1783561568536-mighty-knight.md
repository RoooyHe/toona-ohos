## Goal

Fix the runtime SQLite crash: `no such column: last_event_time in "SELECT * FROM rooms ORDER BY last_event_time DESC"` that occurs when the app loads rooms from an existing database.

## Root Cause

The `RoomEntity` defines `last_event_id` and `last_event_time` columns, and `RoomDao.getAll()` queries `ORDER BY last_event_time DESC`. However, these columns were **never added via an `ALTER TABLE` migration** in `ToonaDatabase.onUpgrade()`. They only exist for **new installs** that run `onCreate()`. Users who upgraded from an earlier database version (v1–v6) never had these columns added.

The migrations in `ToonaDatabase.ets` add: v1→v2 (canonical_alias, join_rule, etc.), v2→v3 (tags), v3→v4 (crypto tables), v4→v5 (device_keys), v5→v6 (device_keys trust columns). **None include last_event_id or last_event_time**.

## Design

1. **Add migration v6→v7** that adds the missing columns:
   ```sql
   ALTER TABLE rooms ADD COLUMN last_event_id TEXT
   ALTER TABLE rooms ADD COLUMN last_event_time INTEGER
   ```

2. **Increment database version** from 6 to 7 in the `@Database` decorator.

3. **Add the `if (oldVersion < 7)` migration block** following the existing pattern in `onUpgrade()`.

## Key Files

- [ToonaDatabase.ets](toona/src/main/ets/database/ToonaDatabase.ets) — add v7 migration, bump version
- [RoomDao.ets](toona/src/main/ets/database/dao/RoomDao.ets) — no changes needed (query is already correct)
- [RoomEntity.ets](toona/src/main/ets/database/entities/RoomEntity.ets) — no changes needed (columns already defined)

## Execution Sequence

1. In `ToonaDatabase.ets`:
   - Change `@Database({ ..., version: 6 })` → `version: 7`
   - Add new block after the v6 migration:
     ```typescript
     if (oldVersion < 7 && newVersion >= 7) {
       const migrations = [
         'ALTER TABLE rooms ADD COLUMN last_event_id TEXT',
         'ALTER TABLE rooms ADD COLUMN last_event_time INTEGER'
       ];
       for (const migration of migrations) {
         try {
           db.executeSql(migration);
           logger.info(`Migration v6→v7 succeeded: ${migration}`);
         } catch (error) {
           logger.error(`Migration v6→v7 failed: ${migration}`, error);
         }
       }
     }
     ```
2. Run `arkts_check` on `ToonaDatabase.ets`
3. Run `hvigor build` to verify
4. Commit and push

## Verification

| Check | Method |
|-------|--------|
| ArkTS syntax | `arkts_check` on ToonaDatabase.ets |
| Compilation | `hvigor build` |
| Runtime | Install on device with existing DB → room list loads without crash |

## Risks And Compatibility

- **Safe for existing users**: `ALTER TABLE ADD COLUMN` is idempotent-safe because the migration is gated by `oldVersion < 7`. If the column already exists (new installs), this migration block simply won't run.
- **If column already exists**: The `ALTER TABLE` will fail with "duplicate column" error, but it's caught by the try-catch, so it's harmless.
- **No data loss**: Adding columns with no DEFAULT stores NULL for existing rows, which is fine since the code already handles `undefined`/null for these fields.

## Rollback

- Revert `ToonaDatabase.ets` to version 6 (undo version bump and remove v7 migration block)
- Or: delete the app's database on device (`toona_matrix.db`) to force a clean `onCreate`
