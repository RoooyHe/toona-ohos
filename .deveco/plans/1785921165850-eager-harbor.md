# Goal

Eliminate all counterfeit (fake-but-looks-real) crypto code. Every method that previously produced **wrong output silently** now either:
1. Throws `Error('E2EE not available — encryption is not yet implemented')`, or
2. Returns a clear fallback value with honest logging

No method should **pretend** to work. The UI must tell the user "not supported" rather than showing fake verification codes or fake decryption results.

# Scope / Non-goals

**In scope:**
- OlmWrapper → `CryptoStub` (all 12 fake methods become honest stubs)
- CryptoService (skip key gen/upload, keep session storage pipeline, honest key-sharing stubs)
- VerificationService (honest stubs — refuse to start, never mark verified)
- UI surfaces that display crypto/verification state (SettingsPage, MessageBubble, verification dialogs)

**Not in scope:**
- Real Olm/WASM integration (separate future work)
- Database schema changes (keep existing tables for future real-Olm use)
- CryptoTypes.ets (types are correct — keep them as-is for future compatibility)
- CryptoDao/DeviceKeysDao (the storage layer is real — keep it)

# Design

## 1. OlmWrapper → CryptoStub

Rename `OlmWrapper.ets` to `CryptoStub.ets`. Keep `MegolmSession` class and `base64Encode`/`base64Decode` utilities (they're real, not fake). Stub every other method:

| Method | New behavior |
|--------|-------------|
| `initialize()` | Log "CryptoStub initialized (E2EE not available)" |
| `generateDeviceIdentity()` | Throw `Error('E2EE not available — device identity generation requires real Olm')` |
| `generateRandomKey()` | Throw `Error('E2EE not available — cryptographic random generation requires real Olm')` |
| `signDeviceKeys()` | Throw (never called — generateDeviceIdentity throws first) |
| `createInboundGroupSession()` | **KEEP** — just creates a data object storing raw key for future use. No fake decryption involved. |
| `decryptGroupMessage()` | Return `null` with error log "Decryption not available — E2EE not implemented" |
| `parseDecryptedMessage()` | **KEEP** — just JSON.parse, not fake |
| `pickleSession()` | **KEEP** — just JSON+base64 serialization (key param already ignored, document it honestly) |
| `unpickleSession()` | **KEEP** — just base64+JSON deserialization |
| `sha256()` | Throw `Error('E2EE not available')` |
| `hmacSha256()` | Throw `Error('E2EE not available')` |
| `aesCtrDecrypt()` | Throw `Error('E2EE not available')` |
| `ed25519Sign()` | Throw `Error('E2EE not available')` |
| `deriveKeyMaterial()` | Throw `Error('E2EE not available')` |
| `constantTimeCompare()` | **KEEP** — real algorithm, no security harm |
| `base64Encode()` | **KEEP** — real encoding |
| `base64Decode()` | **KEEP** — real decoding |
| `canonicalJson()` | **KEEP** — real utility |

Export `CryptoStub` class and `MegolmSession` class. Delete `KeyMaterial` interface (only used by `deriveKeyMaterial`).

## 2. CryptoService changes

### `initialize()`
- Skip `OlmWrapper.generateDeviceIdentity()` and key upload
- Log "CryptoService initialized (E2EE not available — encryption stubs active)"
- Set `this.initialized = true` (so the pipeline still routes events)
- **Keep** `loadCachedSessions()` (for future real-Olm use)
- **Skip** `ensureKeysUploaded()` and `ensureOneTimeKeys()` — these generated/uploaded fake keys

### `getOrCreateDeviceId()`
- If no existing device ID in database, generate a simple `TOONA_<random_hex>` using `util.generateRandomUUID()` or timestamp-based ID
- **No fake key generation** — just a device ID for API calls

### `getOrCreateDeviceKeys()`
- If no existing keys in database, set `this.deviceIdentity = null` and log "Device keys not available — E2EE not implemented"
- Don't generate fake keys

### `decryptEvent()`
- **Keep the session lookup pipeline** (check cache → check DB → queue as pending)
- When session is found, call `CryptoStub.decryptGroupMessage()` which returns `null`
- Return `createDecryptionError(event, 'E2EE not available — decryption requires real Olm library')`
- When session is not found, return the existing "No session available" error

### `sendKeyShareResponse()`
- Log "Key sharing not available — E2EE not implemented"
- Don't attempt to send

### `requestRoomKeys()`
- Log "Key requests not available — E2EE not implemented"
- Don't attempt to send

### `handleRoomKeyEvent()` — **KEEP as-is**
- Still creates inbound group session via `CryptoStub.createInboundGroupSession()`
- Still stores in cache and database
- Still calls `processPendingEvents()` (even though it's a no-op)
- This is the session storage pipeline we're preserving for future real-Olm

### Verification event handlers — **KEEP delegation**
- Still delegate to VerificationService (which will now be honest stubs)

### `uploadDeviceKeys()` / `uploadOneTimeKeys()`
- Change to throw `Error('E2EE not available')` since they would upload fake data

### `processPendingEvents()`
- Already a no-op — just add honest log "Decryption pending events skipped — E2EE not available"

## 3. VerificationService changes

### `startSasVerification()`
- Throw `Error('Device verification not available — E2EE not implemented')`

### `startQrVerification()`
- Throw `Error('QR verification not available — E2EE not implemented')`

### `acceptVerification()`
- Log "Verification not available — E2EE not implemented"
- Don't change session phase

### `handleVerificationRequest()` through `handleVerificationDone()`
- Log the event receipt honestly
- **Don't** change session phases or mark anything verified
- `handleVerificationDone()` — **don't** call `setTrustLevel(VERIFIED)`, just log

### `confirmVerification()`
- Throw `Error('Device verification not available — E2EE not implemented')`

### `generateSasBytes()` / `generateSharedSecret()`
- Delete or throw (never called since startSasVerification throws)

### `getSasDigits()`
- Return a `SasDigits` with `decimal: 'N/A'` and `emoji: ['⚠️']` — honest indicator

### `getDeviceTrustLevel()` / `setDeviceTrustLevel()`
- **KEEP** — these are just database reads/writes, not fake crypto

### `getSession()` / `getActiveSessions()` / `getSessionForDevice()`
- **KEEP** — just data access, not fake

### `cancelVerification()`
- **KEEP** — just removes session from map

## 4. UI updates

### SettingsPage
- `toggleE2EE()`: Show `ToastUtils.show('端到端加密暂不可用')` instead of attempting fake initialization
- `loadEncryptionStatus()`: Set `isE2EEEnabled = false` always, don't call `cryptoService.isInitialized()` for this flag
- `startDeviceVerification()`: Show `ToastUtils.show('设备验证暂不可用')` (already does this — confirm no change needed)
- E2EE toggle section: Show "加密功能暂不可用" text instead of toggle

### MessageBubble
- `buildEncryptedMessage()`: Replace "Unable to decrypt" + retry with "🔒 加密消息暂不可读" (encryption not supported)
- Remove the retry button (since key requests are no-ops)
- Keep the visual structure (lock icon + message)

### Verification dialogs
- SasVerificationDialog: Wrap `verificationService.getSasDigits()` in try-catch; on error, show "验证不可用"
- QrCodeVerificationDialog: Similar try-catch
- VerificationRequestDialog: `acceptVerification()` in try-catch, show "验证不可用" on error

## 5. EventProcessor

- Remove `import { OlmWrapper }` (line 6) — unused since `attemptDecryptionFromCache()` always returns `null` anyway
- No other changes needed — the `processEncryptedEvent()` pipeline already falls through to `createEncryptedEventResult()` when decryption fails

# Risks And Compatibility

- **Risk**: `attemptDecryptionFromCache()` in EventProcessor already returns `null` always — no behavior change there
- **Risk**: SyncManager calls `cryptoService.initialize()` — we must still set `initialized = true` or SyncManager errors. Our stub initialize() will do this.
- **Risk**: DeviceHttpClient still has uploadKeys() method — it's a real HTTP client, we just won't call it with fake data
- **Compatibility**: CryptoDao/DeviceKeysDao tables and SQL remain unchanged — future real-Olm integration can reuse them
- **Compatibility**: CryptoTypes.ets interfaces remain unchanged — future real-Olm implementation targets the same types
